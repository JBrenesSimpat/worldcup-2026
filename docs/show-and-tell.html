Decisions, made together

What I asked → what we chose

React? Backend? Database?
Next.js, no server, no DB — keep it static
Where to publish — free?
Vercel + GitHub, $0
Make it multi-language
Spanish default + English toggle
Show times in Mexico time
Mexico default, with a local-time switch
Update after every game?
Auto-poll during matches, free
“Where does the data come from?”

Two official feeds, stitched together

football-data.orgteams · fixtures · scores · winners
fixturedownload.comstadium per match

We matched them on exact kickoff time + teams — 104/104 venues mapped.

  • The API lacked flags & Spanish names, so we added those ourselves
  • Stored as plain JSON in the repo — no database needed

A habit that paid off

“It’s not filtering” → let’s check

  • I noticed a team filter looked off on my phone
  • Instead of guessing, it checked the real data — the logic was correct (Portugal → 3 games)
  • Turned out to be a display quirk, re-verified on the live site

The pattern throughout: verify against real data and the live app — don’t assume.

What made it work

Lessons from the build

  • Ask, then decide — clear questions up front avoided rework
  • Plan first — a phased roadmap kept it on track
  • Keep it simple — static + no DB made it free and reliable
  • Verify every step — build, deploy, and check the live app
  • Let automation do the boring part — results update themselves
